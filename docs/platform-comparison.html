CC Fleet and CC HostCC Fleet 与 CC Host

CC Fleet and CC Host · current gateway comparisonCC Fleet 与 CC Host 对比 · 当前网关路线

Our current gateway and CC Host’s documented setup both use a remote address and access key for local Claude Code. The main differences are which accounts may be selected, how routing chooses them, and which internal behavior we have verified.我们的新网关与 CC Host 文档中的接入方式，都使用“远程地址＋接入密钥”连接本机 Claude Code。主要区别在于：允许选哪些账号、按什么规则选择，以及哪些内部行为已经得到验证。

Two seats, one reception desk两个账号座位，一个收件前台

Imagine you own A and B. In Fleet, selecting only A means no automatic use of B. Selecting A then B permits eligible fallback; pinning a launch to A disables that cross-account switch. Sticky mode remembers which account began a normal response; that memory can expire or reset.假设你拥有 A、B 两个槽位。在 Fleet 中，只选 A 就不会自动使用 B；选了 A、B 并安排顺序，才允许在符合条件时尝试备用账号。如果本次启动明确指定 A，就关闭跨账号切换。“会话保持”会记住开始正常响应的账号，但这份记忆可能到期或被重置。

CC Host’s docs also allow choosing accounts and backups, but its random sticky policy and available shared-account options differ. A similar front door does not make the two systems identical. See the detailed A/B examples for Fleet’s rules.CC Host 文档也支持选择账号和备用账号，但默认随机策略与可使用共享账号的范围有所不同。入口看起来相似，不代表内部系统完全相同。Fleet 的具体规则见上方 A／B 示例。

Encryption and fingerprints: HTTPS does not hide model context from a gateway that terminates it. Fleet’s outgoing Python TLS connection has not been proven equivalent to native Claude Code’s JA3 fingerprint. CC Host’s TLS/SSH internals and fingerprint behavior are also unverified here. This comparison does not establish provider approval for either design.加密与连接指纹：HTTPS 不能向负责解密的网关隐藏模型上下文。Fleet 由 Python 发起的上游 TLS，未证明与原版 Claude Code 的 JA3 指纹相同。本次也未验证 CC Host 内部的 TLS／SSH 或指纹行为。这份对比不构成服务商对任一设计的认可。
