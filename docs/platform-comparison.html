01

Two Devin doors, one local workbench两种 Devin 入口，同一个本地工作台

Your computer is the workbench. Fleet is the receptionist. Native Devin is the remote thinker. The two doors below use different accounts and different admission rules.电脑是工作台，Fleet 是接待前台，原生 Devin 是远端负责思考的智能体。下方两个入口使用不同的账号与准入规则。

Three names, three jobs: Claude Code is the local app and tool runner; native Devin is the remote agent; Opus 5.5/max is the reviewed model setting used by these pilot profiles. The app, agent harness and underlying model are separate layers.三个名称，三种工作：Claude Code 是本地应用与工具执行端，原生 Devin 是远端智能体，Opus 5.5／max 是这些试点配置经审核的模型设置。应用、智能体框架和底层模型是不同层。

Private account: your locked room私人账号：你自己的房间

You hold a private Fleet slot and sign in to Devin on that slot. Your Fleet connection key can select only your verified own slot. The native Devin credential remains there; the local client receives a separate Fleet key.你持有私人 Fleet 槽位，并在该槽位登录自己的 Devin。Fleet 连接密钥只能选择已验证的自有槽位；原生 Devin 凭证留在槽位，本地客户端使用另一个独立的 Fleet 密钥。

The own-account route is operator enabled. A fresh identity/runtime check is required before the account page offers it; Anthropic remains the default provider.自有账号路线由运营方启用。账号页面提供该选项前，需要新鲜的身份及运行环境验证；默认提供商仍为 Anthropic。

Trial pilot: a separate demo room试用：独立的体验房间

Sign in to Fleet with a verified Google account and obtain a trial key. No private slot purchase or personal Devin login is required. A dedicated Fleet-managed worker uses the operator’s trial account; it never borrows a customer’s private slot.通过已验证的 Google 账号登录 Fleet，取得试用密钥，无需购买私人槽位或登录个人 Devin。专用的 Fleet 试用工作进程使用运营方的试用账号，不借用客户私人槽位。

Trial access has separate keys, a separate allowance ledger and one executing turn globally. The key gives trial access, not access to private customer slots or the provider credential.试用拥有独立的密钥、额度账本，并且全局同时只执行一轮。试用密钥只提供试用权限，不授予客户私人槽位或服务商凭证的访问权限。

These are technical pilot routes. The operator-managed free trial is separate from private own-account service and is not evidence of a commercial subscription-resale agreement.这是技术试点路线。运营方管理的免费试用与私人自有账号服务分开，也不代表取得了商业订阅转售协议。

02

Inside the private Devin route私人 Devin 路线内部怎样工作

The passport check身份与权限检查

“Logged in” and “ready for this request” are separate checks. Fleet verifies the current slot owner and rental claim, the provider-account identity, the approved native CLI/adapter/model mapping, and a fresh readiness observation. Changed or revoked bindings invalidate old endpoint generations.“已经登录”和“可以处理这个请求”是两项检查。Fleet 核对当前槽位持有者与租用关系、服务商账号身份、获准的原生 CLI／适配器／模型映射，以及新鲜的就绪观察。绑定改变或撤销后，旧连接版本会失效。

A readiness probe checks metadata without sending a model prompt. It does not promise that the provider will accept every future request or that a plan has unlimited quota.就绪检查读取元数据，不发送模型提示。它不保证服务商会接受未来每次请求，也不表示订阅额度无限。

The translator, not a new model identity适配器负责翻译，不更换智能体身份

Claude Code sends its supported Messages envelope. Fleet carries visible conversation and local-tool history as labeled context, then starts native Devin through ACP—a structured conversation/control protocol. Devin still runs its own agent harness and may introduce itself as Devin.Claude Code 发送受支持的 Messages 请求。Fleet 将可见对话及本地工具历史整理为带标签的上下文，通过 ACP（结构化的会话控制协议）启动原生 Devin。Devin 仍使用自己的智能体框架，也可能正确地自称 Devin。

Private assistant thinking/signature blocks are not carried over as interchangeable reasoning. Accepted cache, thinking and max-token settings do not establish full Anthropic API semantics.私有思考及签名块不会被当成可互换的推理状态移植。接受缓存、思考及最大 token 设置，也不表示实现了完整 Anthropic API 语义。

What is actually pinned and supported?具体固定和支持什么？

The reviewed ordinary profile uses Opus 5.5 with max effort and accepts supported text plus declared local tools. Its formatted visible-context limit remains 256 KiB; tool descriptions and included history count toward it. Native token counting and full API parity are not established. The larger trial request limit and trial native web search are separate policies, not an automatic private-account upgrade.经审核的普通配置使用 Opus 5.5、max 努力级别，支持文字及已声明的本地工具。格式化后的可见上下文上限仍为 256 KiB，包括工具说明与包含的历史。尚未证明原生 token 计数与完整 API 语义一致。更大的试用请求上限与试用原生网页搜索属于独立策略，不会自动升级私人账号路线。

03

Devin thinks; your computer does the file workDevin 思考，电脑执行文件操作

The internal MCP bridge is a controlled mailbox. It exposes the tool descriptions declared by the local client and records a real tool call. After cleanup, Fleet returns that call to Claude Code. Claude Code runs Read, Edit, Write, Bash or a compatible declared tool under its local permission policy.内部 MCP 桥像一个受控信箱，提供本地客户端声明的工具说明，并记录真实工具调用。清理后，Fleet 将调用交回 Claude Code；Read、Edit、Write、Bash 或兼容的已声明工具，按本地权限策略执行。

Conversation continuity lives with the client连续性由客户端保存

The next HTTP request includes visible history and the matching tool result. A new native process/session handles the continuation. Already executed tool results are labeled as history, not instructions to run them again. Idle chats hold no trial worker.下一次 HTTP 请求包含可见历史与匹配的工具结果，由全新的原生进程／会话继续处理。已执行的工具结果会标记为历史，而不是要求再执行一次。空闲聊天不占用试用工作进程。

Three different kinds of web tools三种不同的网页工具

The trial can use its explicitly enabled native Devin web_search remotely. A compatible custom tool declared by Claude Code runs locally. Claude’s hosted WebSearch/WebFetch request format is excluded from this route. These names do not describe the same execution path.试用可以在远端使用明确启用的 Devin 原生 web_search。Claude Code 声明的兼容自定义工具在本机运行；Claude 托管 WebSearch／WebFetch 的请求格式不在此路线支持范围内。这几种名称对应不同的执行路径。

Honest streaming: native generation or tool handoff, usage collection and cleanup complete before the Messages/SSE response is emitted. SSE is the delivery format here; it does not mean live token-by-token native generation. A lost response after dispatch is not blindly replayed.如实说明流式：原生生成或工具交接、用量采集和清理完成后，才发出 Messages／SSE 回复。SSE 是这里的交付格式，不代表原生生成时逐 token 实时传送。派发后丢失的回复不会被盲目重放。

04

The trial receptionist also keeps a notebook试用前台还负责记账

The trial is a separate entrance at /trial/v1/messages. It checks the Fleet trial key and request, checks the worker without a model prompt, then transactionally reserves allowance before dispatch. Its access-key and allowance databases are separate from the product database.试用使用独立入口 /trial/v1/messages。先检查 Fleet 试用密钥与请求，再进行不发送模型提示的工作进程检查，最后在事务中预留额度并派发。访问密钥与额度账本使用独立于产品数据库的数据库。

One demo room; no trial waiting queue一个体验房间，没有试用排队区

Only one trial turn executes globally. If the worker is busy, Fleet returns 429 and asks the caller to wait and submit later. The private gateway’s bounded 30-second queue does not apply to the trial. Replacing a trial key does not reset its account budgets.全局同时只执行一轮试用。工作进程繁忙时，Fleet 返回 429，请调用方稍候再提交。私人网关的有限 30 秒队列不适用于试用；更换试用密钥也不会重置账号额度。

A clean room for each turn每轮使用干净的临时房间

A dedicated non-root worker creates a fresh private HOME with only its provider credential and pinned configuration. It copies no previous conversation directory. After confirmed process cleanup and usage collection, turn artifacts are removed. Uncertain cleanup quarantines artifacts and pauses new trial work.专用的非 root 工作进程为每轮创建私有临时 HOME，只带入所需服务商凭证与固定配置，不复制旧会话目录。确认进程清理并采集用量后，删除该轮产物；清理不确定时隔离产物并暂停新试用任务。

What happens to an uncertain receipt?回执不确定时怎么办？

Complete trusted metering charges the actual sum of input, output, cache-read and cache-creation tokens, including overshoot. When only cache-read metering is missing, a verified model, valid reply and complete cleanup can release the worker while keeping at least the full reservation or larger known subtotal. A separately verified clean five-minute timeout can also release the worker with a retained hold, but returns a timeout, not success.完整可信计量会计入输入、输出、缓存读取和缓存创建的实际总量，超额也计入。只缺缓存读取计量时，若模型已验证、回复有效且清理完整，可释放工作进程，但至少保留整笔预留额度或更大的已知小计。另有明确验证并清理的五分钟超时策略，也可在保留额度后释放工作进程；它返回超时，不会当作成功。

Unknown execution, required usage, model identity or cleanup retains the reservation and pauses for operator review. It does not become zero usage. A daily reset does not erase unresolved holds or clear a safety pause. A proven failure before a model request was sent can release its model/runtime reservation, with an audit row retained.执行情况、必需用量、模型身份或清理未知时，保留预留额度并暂停，等待运营方核实，不会补成零用量。每日重置不会抹去未解决的保留额度或解除安全暂停。若能证明请求尚未发给模型，可退回该轮模型及时间预留，并保留审计记录。

05

Different clocks protect different jobs不同的时钟保护不同环节

Think of the 340-second runtime reservation as booking a room before knowing how long the visit will take. After verified settlement and cleanup, the ledger returns unused seconds. A verified 30-second turn can return 310 seconds from that booking. The 300-second generation deadline remains five minutes; a larger outer timer gives setup and cleanup room, not extra model thinking time.把 340 秒运行时间预留想成先预约房间，再核对实际用时。确认结算及清理后，账本退回未用秒数；已验证的 30 秒轮次可退回该笔预留中的 310 秒。生成截止时间仍是 300 秒，即五分钟；外层时钟较长，是给启动和清理留空间，不是额外思考时间。

Before a model send, Fleet holds up to 20,000 remaining allowance tokens and 340 seconds. The token hold and max_tokens are not enforced upstream spending or output caps; actual reported usage can be larger. Turn handoffs and continuations count separately toward daily turn/runtime limits. Here, one turn means one accepted Fleet model request; a native agent may make several internal provider calls, so this is not a provider billing-request count. Reset is at 00:00 UTC.发送模型请求前，Fleet 预留最多 20,000 个剩余额度 token和 340 秒。Token 预留及 max_tokens不是上游强制的费用或输出上限；实际报告用量可能更高。工具交接与继续请求分别计入每日轮次／运行时间限制。这里一轮指一次获准的 Fleet 模型请求；原生智能体内部可能发起多次服务商调用，因此不是服务商计费请求次数。每日 UTC 00:00重置。

08

Account control and trust boundaries账号控制与信任边界

You choose the eligible accounts由你确定可选账号

  • A only: selecting A does not permit automatic use of B.只选 A：不会自动使用 B。
  • A before B: eligible fallback can try B after a known pre-send failure or a supported explicit upstream rejection.A 优先、B 备选：发送前已确认的故障，或受支持的明确上游拒绝，才可尝试 B。
  • Sticky mode: new conversations start in your priority order; later requests prefer the account that began a normal response. The bounded assignment can expire or reset.会话保持：新会话按你的优先级开始；后续请求优先使用开始正常回复的账号。有限的运行时记录可能到期或被重置。
  • Pin this launch: ccfleet local --slot A disables cross-account switching for that launch.固定本次启动：ccfleet local --slot A 会关闭本次启动的跨账号切换。

Content and credentials are different内容与凭证，分别看待

The laptop holds a separate, revocable Fleet connection key. The selected slot keeps its native Claude or Devin credential. Slot isolation does not hide model content from the gateway, slot or chosen provider.电脑保存独立且可撤销的 Fleet 连接密钥；所选槽位保留原生 Claude 或 Devin 凭证。槽位隔离不会向网关、槽位或所选服务商隐藏模型内容。

HTTPS ends at the gateway, which can read requests and responses. Privileged machine administrators retain root access. Files remain local as files, but prompts, file contents and tool results can enter model context.HTTPS 在网关解密，因此网关可读取请求与回复。主机管理员仍拥有 root 权限。文件本身留在本地，但提示、文件内容与工具结果可能进入模型上下文。

If sending is uncertain or public response headers have started, Fleet does not switch and replay the request. A dispatched native Devin request is not automatically replayed.发送结果不确定或已经返回公共响应头后，Fleet 不会换账号重放请求。已派发的原生 Devin 请求也不会自动重放。

09

When many agents ask at once很多代理同时提问时

Think of Fleet as a shared reception desk outside private rooms. Your slot and provider account stay yours. The desk has limited space to handle questions and a small waiting area for a rush.把 Fleet 想成私人房间外共用的收件前台。槽位和服务商账号仍归各自所有；前台一次能处理的问题有限，突然来很多问题时，还有一个小等候区。

1. Check the ticket1. 检查通行证

Fleet checks the connection key and the slots it is allowed to use. The parent agent, its subagents and other chats using that same key share one traffic limit.Fleet 先检查连接密钥，以及它获准使用的槽位。主代理、子代理和使用同一密钥的其他会话，共享同一连接的请求上限。

2. Wait for room2. 没空位就稍候

If there is no room, an extra request may wait for up to 30 seconds by default. Model work has not started for that waiting request. Once room opens, the oldest waiting request that currently fits can go next.没有空位时，额外请求默认可以等待最多 30 秒；等候中的请求尚未开始模型任务。有空位后，当前符合条件的请求中，等候最久的可先开始。

3. Use your own room3. 进入自己的房间

Before sending it, Fleet checks that the key and account choices are still valid. Waiting never adds another customer's slot, changes the chosen provider account or increases a subscription allowance.发送前，Fleet 再检查密钥和账号选择是否仍有效。排队不会增加别人的槽位、改变选定的服务商账号，或增加订阅额度。

Working places and waiting places处理名额与等候名额

The default gateway ceilings are 16 active requests in total, at most 8 on one connection key. Another 16 may wait in total, at most 8 on one key. An active place remains occupied until the response finishes or that request is closed.网关默认最多同时处理 16 个请求，同一连接密钥最多 8 个；另有总共 16 个等候名额，同一密钥最多等候 8 个。正在处理的名额会一直占用到回复结束，或该请求被关闭。

For example, when eight requests on one key are already active, a ninth can wait rather than fail immediately, provided the waiting area has room. An agent that is idle makes no model request and uses no active place.例如，同一密钥已有 8 个请求正在处理时，只要等候区有空位，第 9 个可以稍候。闲置的代理没有发出模型请求，就不占处理名额。

These are configurable ceilings, not reserved seats. Large requests, shared traffic or fewer available connections can leave fewer places. Fleet also leaves connection headroom for the website and machine reports. The free daily trial has separate limits.这些是可以配置的上限，不是保证预留的座位。请求很大、共享流量较多，或可用连接较少时，能用的名额可能更少。Fleet 也为网页与机器状态报告留出连接余量。免费每日试用另有独立限制。

A big conversation is a heavier bag长对话就像更重的书包

A question can carry a long conversation, file text and tool results. Fleet therefore checks both the number of active questions and their combined message size. By default, one request can be up to 16 MiB, with a shared 32 MiB budget for admitted request bodies.一个问题可能带着很长的对话、文件文字和工具结果。因此 Fleet 不仅数正在处理的问题，还检查它们合计有多大。默认单个请求最多 16 MiB，已获准处理的请求正文合计上限为 32 MiB。

A waiting request is not loaded into the application's body-processing budget yet. Once a message is prepared for forwarding, spare raw and decoded copies are released before streaming the answer. The gateway still receives and processes model content; waiting is not a promise that content stays only on your computer.等候中的请求还没有进入应用的正文处理额度。消息准备好转发后，会在流式返回答案前释放多余的原始正文与解码副本。网关仍会接收和处理模型内容；排队不表示内容只留在你的电脑上。

MiB measures how much data a message carries. This size budget helps protect memory. It is not the whole server's RAM limit, a model context allowance, a token quota or a price.MiB 用来衡量消息携带的数据大小。这个大小上限帮助保护内存；它不是整台服务器的内存上限，也不是模型上下文额度、token 配额或价格。

One busy line does not freeze every line一条队伍繁忙，不堵住其他队伍

Suppose one key has used all eight of its active places. Its next request waits, but another key can still use an available place. Fleet picks the oldest request that currently fits the key, gateway and size limits, rather than letting one blocked request hold everyone behind it.假如一个密钥的 8 个处理名额已用满，它的下一个请求要等候；其他密钥仍可使用空余名额。Fleet 会从当前符合连接、网关和大小限制的请求中，选择等候最久的，避免一个暂时无法开始的请求堵住所有人。

This does not promise a fixed start order or identical waiting times for every person. The limits are per connection key, and all users still share the gateway's overall ceilings.这不保证每个人都按固定顺序开始，或等待同样长时间。连接上限按密钥计算，所有用户仍共享网关的总上限。

Leaving the line and changing the ticket退出队伍与更换通行证

A detected disconnect, an expired wait or a shutdown removes that waiting request. If a key is revoked or its slot selection changes while waiting, Fleet checks it again when a place opens and refuses the old request before dispatch.检测到断开连接、等候超时或服务关闭时，会移除该等候请求。等候期间如果密钥被撤销，或槽位选择发生变化，空位出现后 Fleet 会再次检查，在派发前拒绝旧请求。

Cancellation cannot undo model work that already started. After a gateway restart, a waiting request must be submitted again; the waiting area is not a saved job list.取消不能撤回已经开始的模型任务。网关重启后，等候请求需要重新提交；等候区不是持久保存的任务清单。

If you still see a busy error如果仍看到忙碌错误

A full waiting area or an expired wait (30 seconds by default) can still return HTTP 503. For a Fleet admission refusal, that request has not been sent for model work. Follow the retry delay, reduce simultaneous agents if needed, check completed or partial results, and resume only unfinished work. No reinstall or new provider login is needed for this capacity error.等候区已满，或等候超时（默认 30 秒）后，仍可能返回 HTTP 503。如果是 Fleet 的准入拒绝，该请求尚未发出执行模型任务。请遵循重试等待时间，必要时减少同时运行的代理，检查完整或部分结果后，只继续未完成的工作。这种容量错误无需重装或重新登录服务商。

A connection breaking after work starts is different: the model may already have acted. Fleet does not blindly replay an uncertain request. A retry delay is guidance, not permission to automatically repeat every failed request; clients must also respect no-retry instructions.任务开始之后断线是另一回事：模型可能已经执行。Fleet 不会盲目重放结果不确定的请求。重试等待时间只是指引，不代表可以自动重复所有失败请求；客户端也要遵守禁止重试的指示。

How operators update it: pause new starts, let existing replies finish, then replace the gateway and reopen traffic after checks. If current work has not finished within the maintenance window, operators should postpone the update and reopen traffic. This is an operator procedure, not an automatic promise of uninterrupted restarts.运营者如何更新：先暂停新任务开始，等现有回复结束，再更换网关并在检查后恢复流量。如果当前任务未在维护窗口内结束，运营者应推迟更新并恢复流量。这是运营流程，不表示重启会自动保持所有请求不中断。
