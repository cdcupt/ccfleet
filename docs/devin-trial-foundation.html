Devin guide · Engineering preparation · October 20, 2026

One account. One short trial.

This is an offline foundation, not an available offer. No website button, CLI command, live API route or provider adapter opens access. The existing private own-account pilot is unchanged.

Think of this as a ticket desk with its door still locked. It can record who has used one ticket, stop duplicate visits and reserve a short turn. It cannot run Devin or share anyone’s Devin account.

The proposed trial limits

Who gets a ticket?A verified Fleet account gets one lifetime attempt. This means one per Fleet account, not proof that a person has only one account.
How long?The ticket expires after at most 10 minutes. Agent work can reserve at most 120 seconds in total, with at most 60 seconds for one step. Unused reserved time is not refunded.
How much work?At most five agent steps. Each incoming request is limited to 64 KiB. This is a byte limit, not a token allowance.
Can everyone enter?Only one trial can be open globally. When busy, the desk refuses the next request immediately; it does not create a waiting queue or consume that person’s attempt.
Can I stop?Cancellation immediately revokes the ticket. It cannot be reopened. A future worker must keep checking the ticket and stop its actual process.
Does each visitor get fresh history?Every trial gets a new random history namespace. A future adapter must create a fresh native session in that namespace and prove worker and history cleanup before admitting another visitor.
What if cleanup fails?All future admissions pause. An expired running step or missing history cleanup also pauses admissions. A later cleanup receipt does not automatically remove that pause.

What the code does today

ccfleetd/devin_trial.py stores only local reservation records in a dedicated SQLite ledger. It defaults to disabled and rejects a database that contains other product tables. SQLite transactions and a uniqueness constraint guard simultaneous admissions. The ledger keeps a hash of the trial secret and stores no prompts, replies or provider credentials.

The caller must obtain the account identity and verified status from Fleet’s trusted sign-in checks. A visitor cannot establish that status by submitting a field. Cleanup receipts also require a trusted future supervisor; they are not visitor assertions.

What still keeps the door locked

  1. Appropriate provider access rights. Pro and Max are individual plans. Public access and resale are not enabled. See Devin’s plan rules and Cognition’s policy.
  2. A real isolated worker. It must enforce deadlines, keep rechecking revocation, use a new native session and history per trial, terminate owned processes and attest cleanup. This foundation does none of those provider actions.
  3. A verified spending boundary. Request, step and time limits are not hard dollar caps. Native max_tokens context is not an enforced spending cap.
  4. Authenticated product integration and release checks. There is no trial route, visitor key issuance, public button or live configuration switch in this change. The offline tests cannot prove live provider behavior.

No purchase, provider message, model request, account change or deployment is needed to test this foundation.
