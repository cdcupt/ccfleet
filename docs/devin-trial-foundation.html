One verified account. A new allowance each UTC day.

每个已验证的 CC Fleet 账号，每天有自己的额度。每天按 UTC 零点重新计算。

Technical foundation only — disabled, no public trial. This draft adds an offline ledger, not a website button, CLI route, shared credential or running Devin worker. Provider access arrangements remain required before offering shared access. No provider contact or live request is performed by this code.

Think of a meter checked before and after a turn

Before one turn starts, the ledger reserves the smaller of the user's remaining daily allowance and the shared daily allowance. Only one user can be active on this ledger at a time. After the worker finishes and cleanup is confirmed, a trusted supervisor supplies the complete measured token total. The ledger counts that total and makes any unused reservation available again.

An ongoing turn can go over the allowance. The current native bridge validates max_tokens but does not forward it as an enforced generation limit. Native usage is collected after the turn. This is a daily reported-token admission budget, not a hard token stop, dollar cap or guarantee about the Devin subscription quota. An overshoot is charged in full and blocks new work when the user or shared allowance is exhausted.

这是“开始前预留、结束后按可信用量记账”的每日准入额度，不是生成到某个 token 就能强制停止。一次任务可能超额；超出的实际用量也会完整记账。用量缺失不能当成零。

Offline defaults

ControlWhat the draft enforces
Daily reported tokens100,000 per verified Fleet account; 1,000,000 across the dedicated ledger. These are configurable offline defaults, not an available product or the provider's quota.
Daily reset00:00 UTC. The allowance DTO shows the day, reset timestamp, reported usage, reservations and remaining user/shared tokens. Previous days remain recorded. Reopening the DB does not refill the same day or change its configured limits.
ConcurrencyOne open/closing lease globally and per account. A step reserves the whole remaining allowance before any future provider call; concurrent requests cannot reserve it twice. Busy requests are refused, with no queue.
Request and time limits64 KiB per request, at most 5 steps per lease, 60 reserved seconds per step, 120 per account/day, and 1,200 globally/day. At most 20 step requests and 5 leases per account/day; 100 steps and 50 leases globally/day. Time/request reservations are not refunded.
Lease and historyA ticket lasts at most 10 minutes and never crosses UTC midnight. Each lease has a new random history namespace. The future worker must isolate and clean both worker state and history.
Unknown usage or cleanupOnly a complete VerifiedUsage from the trusted future supervisor plus confirmed cleanup can settle tokens. Missing/partial usage, unconfirmed cleanup, an overdue worker or a regressed clock retains denial and latches a ledger pause. Day rollover does not erase uncertainty or unpause the ledger. An explicitly measured zero is accepted; a missing count is never invented as zero.

Other request/time/lease limits can deny a new task while a token balance remains. The DTO's enabled/paused fields and admission decision must also be respected. A permit reserves admission only; it is never a Fleet/provider API key or proof that an upstream hard limit exists.

What is implemented

ccfleetd/devin_trial.py is not imported by production Store migrations or routes. It rejects product databases and the earlier one-time draft schema. It uses a separate fresh SQLite ledger, immediate transactions, unique active-session indexes, hashed lease secrets and durable UTC-day counters. It stores no prompts, replies, provider credentials or account subjects. The constructor defaults to disabled; enabling an in-memory instance does not execute an agent.

Before any public access

  1. Provider arrangement. Establish permitted access before using the operator's account for other users. This draft enables no access and performs no outreach.
  2. A trusted isolated worker and usage adapter. Use a fresh session/history, recheck revocation, enforce the separate request/time deadlines, terminate owned processes safely and attest cleanup. Match complete final measured usage to the correct turn; missing native records cannot be converted to zero. Do not deserialize VerifiedAccount or VerifiedUsage from visitor JSON.
  3. Authenticated product integration and release verification. There is no public route, button, visitor key issuance or live switch here. Offline tests do not prove provider behavior, account-sharing permission or a native hard token cap.
