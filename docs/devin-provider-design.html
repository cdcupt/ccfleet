Devin as a substitute inference provider

Preparation only. The Messages codec is disconnected. No customer provider selector or Devin inference route is enabled. Authentication, actual account entitlement/billing and unchanged native Claude Code compatibility remain activation gates.

The product requirement is official Claude Code CLI → the existing Fleet Messages endpoint → the website-selected Anthropic or Devin provider. Tools and project work stay in Claude Code. Separate agent jobs, MCP orchestration, ACP hosting and cloud Sessions are outside this integration.

Published provider contract

The Cognition-scoped OpenCode integration, version 0.3.0, provides the candidate interface. Its published source registers an OpenAI-compatible inference provider and authenticates through Devin's CLI PKCE flow. Registry scope, maintainers and trusted-publisher metadata support publisher attribution; the linked source repository was not publicly accessible, and this does not establish a Fleet redistribution agreement or a support commitment.

  • Deployment constants: the inference origin is https://server.codeium.com, with /api/v1/models, /api/v1/chat/completions and /api/v1/responses.
  • Authentication: browser PKCE at app.devin.ai/auth/cli/continue, an exact-state loopback callback or manual code, and code exchange at api.devin.ai/auth/cli/token. The returned session credential is sent as Bearer authentication. Never put authorization codes or tokens in argv, prompts, logs or public records.
  • Model configuration: use account-discovered concrete model/variant IDs. Catalog cost placeholders are not billing evidence. Generic reasoning-effort controls cannot be assumed equivalent to model variants.

The published cloud Sessions API is a different agent interface. It is not a replacement for a model-completion contract. Unofficial private-RPC bridges, client-identity impersonation, shared-account pools and provider failover are unnecessary for this candidate interface.

ccfleet_agent/devin_protocol.py handles a bounded text-and-tools slice. It requires an explicit alias-to-exact-model map, validates upstream model identity, preserves native tool calls/results and enforces requested tool-choice and parallel-call restrictions. Unknown or unsupported content fails before an upstream request can be sent. This module has no HTTP transport, credential reader, production registration or retry behavior.

Required ownership and routing boundary

Provider selection belongs to an endpoint/key. Credentials and provider identity belong to that key owner's current claimed slot. Anthropic remains the default. A global operator Devin credential must never serve unrelated customers.

  1. Bind provider-account identity, Fleet owner, slot and rental claim; namespace identity by provider. A token hash is not stable account identity.
  2. Use an explicit provider enum and fixed upstream origins. Never accept caller-selected upstream URLs, secret paths or arbitrary forwarded auth headers.
  3. Include provider-binding generation, exact model-map digest and codec revision in readiness identity and revocation checks. An old Claude-ready result must never prove Devin readiness.
  4. Preserve existing key/claim authorization and the pre-send/no-replay boundary. Provider edits revoke the old key generation; no uncertain request is retried on either provider.
  5. Keep native credential storage private to the slot. Preserve the one-account/node rule and immutable signed client bytes. Use a separate static node relay command behind the existing restricted gateway privilege.

Activation evidence still required

Verify authentication, actual account catalog and exact Claude variant, included-quota billing and overage controls, native text/tool round trips, stream interruption, token counting, thinking/cache behavior, release/reclaim revocation and user-selected website routing. Test with disposable inputs and an explicitly bounded spend policy. Do not infer free usage from catalog pricing placeholders or API access from a successful unauthenticated network connection.

The provider's pricing comparison lists API access for paid plans, but does not prove this specific inference route's quota/billing on an account. The individual-plan rules and resale restrictions still apply. A commercial bundle requires an appropriate written agreement.
