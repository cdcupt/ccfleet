Devin as a substitute inference provider

Native CLI relay candidate; inference remains disabled. Devin login, native catalog discovery and ACP v1 initialization succeeded. No native ACP session or prompt has run. The native controller and alternate HTTP codec remain disconnected from production; no customer Devin selector or inference route is enabled.

The product requirement is official Claude Code CLI → the existing Fleet Messages endpoint → the website-selected Anthropic or Devin provider. The current candidate would run the real Devin CLI on the owner’s slot, with an internal Messages-to-ACP adapter behind that same endpoint. Preserving client-side tools and project behavior is still an unverified requirement. Separate customer agent jobs, MCP orchestration and cloud Sessions are outside this integration.

Reuse the existing slot boundary

Current Anthropic behavior: local Claude Code sends Messages requests to Fleet. The gateway authorizes the endpoint’s owner and claim, then forwards the request over restricted SSH to local_relay.py. That Python relay reads the slot’s native Claude login credential and sends a direct HTTPS POST to Anthropic. It does not pass each prompt into a remote Claude Code process. Native Claude Code supplies login and credential renewal.

The source boundaries are laptop/ccfleet:native_settings, ccfleetd/gateway.py:GatewayRuntime._forward, gateway_transport.py:SSHAttempt, node/slot-entry.sh --gateway-only, local_relay.py:credential/serve_one and agent.py:start_login/maintain_slot_credentials.

Reusable for Devin: the same Fleet endpoint, owner/claim authorization, isolated slot, native login locality, restricted transport, revocation, deadlines and no-replay boundary. New work: provider-specific account/readiness binding and a protocol adapter that drives native Devin ACP and returns truthful Messages responses. Claude OAuth decoding and the Anthropic-only egress policy cannot be reused unchanged.

Native ACP controller foundation

ccfleet_agent/devin_acp.py is a disconnected process/RPC controller with fake-executable tests. An allowlisted native executable and exact model UID are required. Session creation and prompts are blocked by default; initialization is separate. The controller advertises empty client capabilities, cancels permission requests, executes no delegated tool or filesystem requests, bounds protocol input/output and time, and cleans up its owned process group. It reads no credentials; the caller supplies the isolated native environment.

ACP notifications remain opaque observations. Native tool activity must not be relabelled as Anthropic tool_use, and context-window usage must not become invented per-request token counts. Empty client capabilities do not disable the agent’s internal tools; a real prompt needs separately verified containment and tool restrictions.

Alternate published HTTP provider contract

The Cognition-scoped OpenCode integration, version 0.3.0, provides an alternate candidate interface, not the active or preferred native-CLI relay path. Its published source registers an OpenAI-compatible inference provider and authenticates through Devin's CLI PKCE flow. Registry scope, maintainers and trusted-publisher metadata support publisher attribution; the linked source repository was not publicly accessible, and this does not establish a Fleet redistribution agreement or a support commitment.

  • Deployment constants: the inference origin is https://server.codeium.com, with /api/v1/models, /api/v1/chat/completions and /api/v1/responses.
  • Authentication: browser PKCE at app.devin.ai/auth/cli/continue, an exact-state loopback callback or manual code, and code exchange at api.devin.ai/auth/cli/token. The returned session credential is sent as Bearer authentication. Never put authorization codes or tokens in argv, prompts, logs or public records.
  • Model configuration: use account-discovered concrete model/variant IDs. Catalog cost placeholders are not billing evidence. Generic reasoning-effort controls cannot be assumed equivalent to model variants.

The published cloud Sessions API is a different agent interface. It is not a replacement for a model-completion contract. Unofficial private-RPC bridges, client-identity impersonation, shared-account pools and provider failover are unnecessary for this candidate interface.

Pure codec for the alternate HTTP candidate

prepare_request(raw, *, model_map) → PreparedRequest
translate_response(raw, prepared) → Anthropic Messages response
translate_sse(chunks, prepared) → Anthropic SSE bytes

ccfleet_agent/devin_protocol.py handles a bounded text-and-tools slice. It requires an explicit alias-to-exact-model map, validates upstream model identity, preserves native tool calls/results and enforces requested tool-choice and parallel-call restrictions. Unknown or unsupported content fails before an upstream request can be sent. This module has no HTTP transport, credential reader, production registration or retry behavior.

Required ownership and routing boundary

Provider selection belongs to an endpoint/key. Credentials and provider identity belong to that key owner's current claimed slot. Anthropic remains the default. A global operator Devin credential must never serve unrelated customers.

  1. Bind provider-account identity, Fleet owner, slot and rental claim; namespace identity by provider. A token hash is not stable account identity.
  2. Use an explicit provider enum and fixed upstream origins. Never accept caller-selected upstream URLs, secret paths or arbitrary forwarded auth headers.
  3. Include provider-binding generation, exact model-map digest, native executable/protocol identity and adapter revision in readiness identity and revocation checks. An old Claude-ready result must never prove Devin readiness.
  4. Preserve existing key/claim authorization and the pre-send/no-replay boundary. Provider edits revoke the old key generation; no uncertain request is retried on either provider.
  5. Keep native credential storage private to the slot. Preserve the one-account/node rule and immutable signed client bytes. Use a separate static node relay command behind the existing restricted gateway privilege.

Activation evidence still required

For the native-CLI candidate, first prove one contained native text turn and its truthful Messages mapping, including an explicit policy for unavailable usage. Then verify the observed request shapes, exact model/variant behavior, client-side tool round trips, streaming and cancellation, counting/thinking/cache semantics, included-quota billing and overage controls, release/reclaim revocation and website routing. The alternate HTTP candidate additionally needs its model-discovery failure resolved. Use disposable inputs and an explicitly bounded spend policy. Login, catalog discovery, ACP initialization and offline client parsing alone do not authorize production activation.

The provider's pricing comparison lists API access for paid plans, but does not prove this specific inference route's quota/billing on an account. The individual-plan rules and resale restrictions still apply. A commercial bundle requires an appropriate written agreement.
