The HTTPS gateway, explained simplyHTTPS 网关通俗说明

One question, four stops一个问题，四个站点

Think of the gateway as a reception desk and a slot as a seat reserved for one of your own Claude accounts. Your computer sends a question to the desk. The desk chooses an allowed seat; that account requests the answer from Anthropic.

把网关想成收件前台，把槽位想成留给你自己的一个 Claude 账号的座位。电脑把问题交给前台，前台选择一个允许使用的座位，由那个账号请求 Anthropic 回答。

  1. 1. Your computer1. 你的电脑Original Claude Code, tools and history run here.原版 Claude Code、工具和历史在这里运行。
  2. 2. Our HTTPS gateway2. 我们的 HTTPS 网关The gateway checks your key, reads the message and selects your slot.网关检查密钥，读取消息并选择你的槽位。
  3. 3. Your selected slot3. 你选中的槽位Restricted SSH reaches the slot; its native Claude credential stays there.通过受限 SSH 连接到槽位；原生 Claude 凭证留在这里。
  4. 4. Anthropic4. AnthropicThe slot uses HTTPS; Anthropic runs the model and streams the answer back.槽位通过 HTTPS 请求上游；Anthropic 运行模型，沿原路分段返回回答。

Your project stays on your computer. When Claude reads files or tools return results, relevant contents may become model context and travel through this route.

项目留在你的电脑上。Claude 读取文件或工具返回结果时，相关内容可能成为模型上下文，沿这条路线发送。

Install and start安装并开始

First claim a slot and sign in to your own paid Claude account on Your slots. Run the installer in your normal terminal. It reuses an existing pairing and Claude installation; only if asked, paste a fresh code from Connect this computer.

先在我的槽位领取槽位，并登录你自己的付费 Claude 账号。在普通终端运行安装命令，已有配对和 Claude 安装会保留。只有终端要求配对码时，才输入 连接这台电脑生成的新代码。

curl -fsSL https://raw.githubusercontent.com/cdcupt/ccfleet/main/laptop/install.sh | bash -s -- --setup

cd ~/code/my-project
ccfleet local --check
ccfleet local

An already paired computer without a saved gateway can run ccfleet gateway setup. The setup and readiness check make no model request or project upload. The check may wait for the selected slot. Readiness does not guarantee acceptance of the next request.

已配对但没有保存网关配置的电脑，可运行 ccfleet gateway setup。安装和就绪检查不调用模型，也不上传项目；检查可能需要等待所选槽位。显示就绪不保证下一条请求一定被接受。

Choose your own accounts选择你自己的账号

Only your own held slots are selectable. Every slot keeps one bound Claude account; selecting A/B does not merge credentials or combine plan limits. Each slot must be signed in and ready before it can receive requests.

只能选择你自己持有的槽位，每个槽位绑定一个 Claude 账号。选择 A／B 不会合并凭证，也不会叠加订阅额度。各槽位必须已登录并就绪，才能接收请求。

Your choice你的选择Select怎样设置What happens会怎样
Fixed固定账号A only只选 AEvery request uses A. Owning A and B does not mean both answer every question. If A fails, this connection does not add B automatically.每条请求只用 A。拥有 A 和 B，不表示两个账号会一起回答。A 失败时，这个连接不会自动纳入 B。
Priority按优先级选择A first, B secondA 优先，B 备选Each request starts with the first eligible slot. A safe failure can use B. After A recovers and its short cooldown ends, a later request can prefer A again.每条请求先选排序最前的可用槽位，遇到可安全切换的失败才用 B。A 恢复且短暂等待结束后，后续请求可能重新优先用 A。
Sticky保持会话账号A first, B second; keep the conversation on one accountA 优先，B 备选；同一会话尽量保持同一账号The account that starts a normal response is remembered. Later requests in that conversation prefer it while it stays eligible and the assignment is remembered.记住开始正常回复的账号，只要它仍可用、服务仍记得这个选择，同一会话后续就优先使用它。

On Your slots → Connect Claude, give A priority 1 and B priority 2. Leave excluded slots blank; selected priorities must be unique. Choose your policy, then save. The CLI is an alternative; choose the example you need and replace A/B with your slot names:

在我的槽位 → 连接 Claude中，给 A 填 1、给 B 填 2。不使用的槽位留空，排序数字不能重复，选好路由后保存。CLI 也能完成配置；按需求选一条，把 A／B 换成真实槽位名称：

ccfleet gateway setup --slots A --replace
ccfleet gateway setup --slots A B --routing priority --replace
ccfleet gateway setup --slots A B --routing sticky --replace

ccfleet local --slot A

The last command pins one launch to A, already selected in the connection, and disables backup switching for that launch. Sticky routing needs a usable conversation identifier. Without one, priority order applies. The assignment stays in bounded runtime memory for up to 24 hours after a normal response starts; restart, configuration changes or cache eviction can reset it. Conversation history stays local.

最后一条命令把这次启动固定到已选中的 A，并关闭这次启动的备用切换。保持会话账号需要可识别的会话标识；没有标识时按优先级选择。选择保存在有限的运行时内存中，从正常回复开始起最多 24 小时；重启、配置变更或缓存淘汰可能重置它。会话历史仍留在本地。

Understand the address理解连接地址

Base URL: https://ccfleet.daichenlab.com
POST https://ccfleet.daichenlab.com/v1/messages

A Base URL is like a mailbox address saved in your client. Saving it does not start a local HTTP server or store your messages there. https:// means the connection is encrypted; the hostname identifies our service; /v1/messages names the Messages API-compatible operation. The familiar path does not make this hostname an Anthropic server.

Base URL 像客户端保存的收件地址，不会因此启动本地 HTTP 服务，也不表示消息存放在这里。https:// 表示连接加密；域名表示我们的服务；/v1/messages 是 Messages API 兼容操作的路径。路径熟悉，不代表这个域名是 Anthropic 的服务器。

The connection key is the key to our reception desk. It is not the slot's Claude credential or an Anthropic paid API key. Your own Claude subscription is still required.

连接密钥是进入我们收件前台的钥匙，不是槽位的 Claude 登录凭证，也不是 Anthropic 付费 API key。你仍需自己的 Claude 订阅。

When a backup is safe什么时候可以安全切换

Imagine sending a letter. If it never left your hand, you can choose another seat. If the recipient clearly rejects it and the system marks that rejection safe to retry, a backup may work. If the receipt is lost after sending, the letter might already have been read: the gateway stops instead of sending a duplicate.

想象寄信：信还没离开你手中时，可以换一个座位处理。对方明确拒收，而且系统确认这种拒绝可以重试时，也可以尝试备用账号。但信已寄出、只是回执丢了，对方可能已经读过；此时网关会停止，不猜测重发。

Supported explicit upstream rejection or a failure known to occur before sending can try the next selected slot. Once sending has begun, an uncertain result is not replayed. After public response headers are sent, no switching or replay occurs, even if no visible text has arrived. An invalid connection key or malformed request needs correction, not another account. A one-slot or pinned launch cannot use an unselected slot.

请求发送前已确认的失败，或受支持的明确上游拒绝，可以尝试下一个已选槽位。开始发送后，如果结果不确定，就不重发。已向客户端发送响应头后，即使还没看到文字，也不会切换或重放。连接密钥错误或请求格式错误，需要修正问题，换账号不能解决。只有一个槽位或固定启动时，不能使用未选中的槽位。

What encryption does and does not hide加密保护什么

The gateway can read model messages and replies. HTTPS protects the laptop-to-gateway connection, but the gateway decrypts the request to route it. The selected slot and Anthropic also process model context. Keeping files on your computer does not mean file contents can never be sent to the model.

可读取模型消息和回复。HTTPS 保护电脑到网关的连接，但 网关为了路由会解密请求。选中的槽位和 Anthropic 也会处理模型上下文。文件留在本地，不等于文件内容绝不会发给模型。

The relay removes selected headers and top-level structured metadata, not arbitrary personal details in prompts or tools. Native context can include OS, working directory or environment information. Local tools, MCP, hooks, plugins and updates may connect directly from the laptop. Native permissions govern those tools; bypass mode can read, modify, delete or transmit local data without individual prompts.

转发时移除部分请求头和顶层结构化 metadata，不会自动删去提示或工具结果里的任意个人信息。原生上下文可能包含系统、工作目录或环境信息。本地工具、MCP、hooks、插件和更新仍可能从电脑直接联网。工具由原生权限决定；跳过确认的模式可能不逐次询问就读取、修改、删除或发送本地数据。

Machine administrators have root access and can inspect slots. Encryption is not anonymity, a zero-metadata promise, proof of native TLS fingerprint parity or provider approval. Read the privacy page for stored data and retention.

机器管理员拥有 root 权限，能检查槽位。加密不等于匿名、零元数据、原生 TLS 指纹一致或服务商认可。保存数据与时长见隐私说明。

Your two different keys两种不同的钥匙

The Fleet connection key lives in your private client configuration; the Fleet server stores a hash. Cleartext appears once at creation. Use separate keys for different apps, and revoke one without changing the slot's Claude login. The native Claude credential stays in the selected slot, where original Claude owns authentication and renewal. It is not returned to your computer or the gateway.

Fleet 连接密钥保存在你私有的客户端配置中，服务端只存哈希；创建时只显示一次明文。不同应用可使用独立密钥，撤销一把不会改变槽位的 Claude 登录。原生 Claude 凭证留在选中槽位，由原版 Claude 管理认证和续期，不会返回电脑或网关。

ccfleet gateway status
ccfleet gateway remove

Removing a saved gateway revokes its key before removing local configuration. It does not release your slots, delete history or revoke the Claude credential. Replacing a connection creates a new key; revoke an older key explicitly when no existing app needs it. Released slots stop being eligible; reclaiming one does not automatically restore an old selection.

移除已保存的网关会先撤销密钥，再移除本地配置，不归还槽位、不删除历史，也不撤销 Claude 凭证。替换连接会生成新密钥；确认旧应用不再使用后，再主动撤销旧密钥。归还的槽位会失去访问资格，重新领取也不会自动恢复原有选择。

Update the right component更新对应的组件

ccfleet update updates the Fleet client. Update your computer's original Claude Code separately, outside a Fleet session. On Your slots, Claude Code → Update to updates the slot installation and follows Latest; Back to Stable selects Stable. Updating the slot does not update local Claude Code, and already running processes keep their version.

ccfleet update 更新 Fleet 客户端。电脑上的原版 Claude Code 需要在 Fleet 会话外单独更新。在我的槽位中，Claude Code → 更新至 更新槽位安装并跟随 Latest；返回稳定版选择 Stable。更新槽位不会更新电脑上的 Claude，已有进程继续使用原版本。

See the fleet's measured performance查看整体性能观测

The public Status performance panel combines fresh relay reports over seven UTC calendar days, including today. It shows the completed-transfer rate, observed relay attempts, average upstream connection time, average time to the first upstream response body byte, and average full-transfer time. Each timing has its own sample count. The averages are weighted by the number of measurements; these are observations of reported traffic, not an active benchmark.

Think of it as counting deliveries that arrived in full, and how long the upstream reply took to start. It does not rate answer quality. One request can create more than one relay attempt when a backup is used; failures before reaching a relay are absent. First-byte timing excludes the journey from your computer through the gateway and SSH setup, and is not a first-token measurement. These reports do not provide percentiles.

Traffic numbers appear after at least twenty observed attempts, even if only one Fleet user contributes. A published total or average can therefore reflect that one user’s traffic. This performance panel does not list names, message content, individual request records or per-user or per-slot breakdowns. The homepage has a separate public usage ranking with masked nicknames, model details and estimated API-equivalent value. Missing, old or insufficient data stays unavailable until there are enough fresh measurements. Opening Status does not call a model. Read Privacy for what is published.

公开的服务状态性能面板汇总包括今天在内的七个 UTC 日的最新转发报告，展示传输完成率、观测到的转发尝试次数、连接上游的平均时长、收到上游首个正文响应字节的平均等待时间，以及完整传输的平均时长。每项计时分别注明样本数量，平均值按样本数加权；这些是已上报流量的观测，不是主动运行的基准测试。

可以把它理解为统计“多少次投递完整完成”和“上游多久开始回复”。它不评价答案质量。使用备用账号时，一条请求可能产生多次转发尝试；到达转发器前的失败没有计入。首字节时长不包含电脑到网关的传输和 SSH 建立过程，也不是首个 Token 的等待时间。这些报告不能计算百分位数。

观测到至少二十次尝试后，才公开流量数值，即使只有一个 Fleet 用户提供了统计。公开的总量或平均值因此可能反映这一个用户的流量。这个性能面板不列出名称、消息内容、单条请求记录，也不按用户或槽位分别展示统计。首页另有公开的用量排行，包含遮盖后的昵称、模型明细与估算的 API 等价值。数据缺失、过期或不足时，暂不显示数值，直到有足够的新观测。打开状态页不会调用模型。公开范围见隐私说明。

Each timing measure separately needs twenty samples; those samples can all come from a single Fleet user. A timing can stay unavailable even when the overall transfer figures are ready.

每项计时分别需要二十个样本；这些样本可以全部来自一个 Fleet 用户。即使总体传输数字可以公开，某项计时仍可能暂时没有可公开的数据。

A completed transfer needs a successful HTTP reply (2xx) delivered in full. Error replies, cancellations and interrupted transfers count as other outcomes. Both Messages and token-count calls can contribute to these measurements.

成功传输要求 HTTP 回复状态为 2xx，且内容完整传完。错误回复、取消或中断的传输计入其他结果。模型消息接口和 Token 计数接口的调用都可能计入这些观测。

Streamed output rate combines matched native/bridge observations at the node with HTTPS gateway observations, without counting gateway traffic twice. It divides provider-reported output tokens by the time from the first to the last response-body chunk, using summed tokens and summed time across successful, fully delivered /v1/messages streaming replies. A sample needs valid output usage, at least two chunks and at least 100 ms of delivery time. Single-chunk or too-short replies are excluded; buffering can affect the observed rate.

The rate excludes the initial wait, but includes stream pauses, network delivery and all output reported by the provider, including thinking or tool output where counted. Higher means faster delivery for comparable models and workloads; it is not a pure model-speed benchmark. At least twenty eligible replies are required independently of the other five metrics, so either source can remain unknown while the other is ready. Node stream observations stay in a private account-bound seven-day relay file and fresh numeric reports. HTTPS gateway storage contains only anonymous daily sample counts, output-token totals and delivery-time totals for seven UTC calendar days. The public output-rate panel shows no input/cache totals, user/slot/model breakdowns or individual request timestamps. New observations are collected from now on; older traffic is not backfilled. The date shown is the earliest available retained sample day, not the collector's original start date.

流式输出速率合并节点上符合条件的原生／桥接观测与 HTTPS 网关观测，不重复计算网关流量。计算方式为服务商报告的输出 Token 总量，除以从首个到最后一个响应正文分块的时间总和，只统计成功且完整传回的 /v1/messages 流式回复。样本需有有效的输出用量、至少两个分块，且传输过程至少持续 100 毫秒。单个分块或过短的回复不计入；缓冲可能影响观测到的速率。

速率不包含初始等待，但包含流中的暂停、网络传输，以及服务商计入的全部输出，包括被计入的思考或工具输出。模型和工作负载相近时，数值越高表示交付越快；它不是模型本身速度的基准测试。它单独要求至少二十个符合条件的回复，不依赖另外五项指标；因此，一种来源未知时，另一种仍可能已就绪。节点流式观测保存在私有、与账号绑定的七日转发统计文件和最新的数值报告中。HTTPS 网关只在七个 UTC 日期内保留不含身份信息的每日样本数、输出 Token 总量和交付时间总和。公开输出速率面板不展示输入或缓存总量、用户／槽位／模型明细或单条请求时间戳。从现在起收集新观测，不补填历史流量。页面日期表示现有留存样本的最早日期，不是采集器最初启动的日期。

Public measured usage ranking公开的观测用量排行

The homepage ranking is public. It ranks known estimated standard API-equivalent USD values and shows measured token subtotals with a compact model breakdown. Unknown estimates are unranked; unpriced usage is not $0. Tokens include observed input, output and reported cache-read/write amounts over seven UTC calendar days. The primary ranking token total, output count, reply count and dollar estimate use the same priceable cohort. Broader reported totals and older/unpriced tokens appear only in expanded details, under a separate scope. Processed totals include cached context counted again per request, not generated or unique text. K means thousand, M million and B billion; exact counts remain in tooltips. Measurement and pricing coverage are shown. Valid existing aggregate tokens can remain visible without a known model price; model details and estimates use only new model-aware observations, without reconstructing older model details.

Names use only partly masked user-chosen nicknames. Short nicknames are fully masked, and missing nicknames use a generic label, never an email or account ID. Masking is not anonymity: a nickname or usage pattern may identify someone. The ranking may include a single contributor. It shows no prompts, response text, raw errors, hostnames, IP addresses, login accounts or individual request timestamps.

API-equivalent value is an estimate using the cited standard global API rates and an assumed five-minute cache-write price. Actual cache TTL, context and service tiers can change API pricing. Estimates follow reported model labels; the numeric aggregates retain no raw replies and cannot reliably reprice older model/fallback attribution. Partial estimates cover only known priced observations; the remainder stays unknown. This is not a Claude Pro/Max bill, an amount paid, a quota balance or a guaranteed saving. Eligible native, bridge and gateway model calls are counted at the node once; no HTTPS migration or model call is needed to read the page. Coverage remains best effort, not a complete record of all Claude activity. See Privacy for this public disclosure.

首页用量排行对所有人公开，按已知的标准 API 等价值美元估算排序，展示观测到的 Token 小计和简要模型明细。未知估值不参与排名；无法计价的用量不按 $0 计算。Token 包括七个 UTC 日期内观测到的输入、输出和已报告缓存读取／写入数量，排行主表的 Token 总量、输出数量、回复数量与美元估值使用同一可计价批次；更广的上报总量及旧数据／未计价 Token 仅在展开明细中以不同范围展示。处理总量包含每次请求重复计数的缓存上下文，不等于生成或独有的文本。K 表示千、M 表示百万、B 表示十亿，提示信息保留精确数量。页面注明观测与计价覆盖范围。已有经验证的汇总 Token 可以在没有已知模型价格时展示；模型明细和估值只使用新的带模型信息观测，不重建历史明细。

名称只使用用户自己选择的昵称，并遮盖其中一部分；较短的昵称全部遮盖，未设置昵称时使用通用标签，绝不以邮箱或账号 ID 代替。遮盖不等于匿名：昵称或用量模式仍可能让人识别出某位用户。排行可以包含仅一位参与用户，不展示提示词、回复内容、原始错误、主机名、IP 地址、登录账号或单条请求时间戳。

API 等价值采用页面引用的标准全球 API 价格，并假设按五分钟缓存写入价格估算。实际缓存有效期、上下文和服务档位可能影响 API 价格。估值依据上报的模型标签；数值汇总不保留原始回复，不能据此可靠地核验旧模型或回退路线并重新计价。部分估值只覆盖已知且可计价的观测，其余部分仍表示未知。这不是 Claude Pro/Max 账单、实际付款、剩余额度，也不保证节省了这些费用。符合条件的原生、桥接与网关模型调用在节点上只计一次；阅读页面不需要迁移到 HTTPS，也不会调用模型。覆盖仍尽力而为，不代表全部 Claude 活动的完整记录。公开范围见隐私说明。

Gateway machine resources网关主机资源

The Status machine panel shows Fleet's dedicated gateway VPS CPU and estimated memory use, Fleet's data-filesystem capacity, and Fleet's own CPU and memory use against its configured limits. Host figures cover the whole VPS, including system services. The filesystem reading measures capacity, not disk speed or the size of Fleet's folder.

Think of the gateway as a junction. These figures help show whether the junction is crowded. Sustained CPU saturation, little available memory, I/O wait or CPU steal can help explain a slowdown; your network, the selected slot and Anthropic can also take time. One quiet or busy sample alone does not establish a bottleneck.

An optional read-only sampler observes fixed Linux proc and own cgroup v2 counters every fifteen seconds. The page reads cached numbers and makes no model call. CPU percentages need two observations; missing or unsupported readings stay unknown, and stale values are hidden after one minute. Container memory includes cache and kernel charges. CPU quota is a ceiling, not a reserved dedicated core. Infrastructure figures are separate from user traffic and do not require relay attempts or timing samples.

服务状态主机面板展示 Fleet 专用网关 VPS 的整体 CPU 和估算内存占用、Fleet 数据所在文件系统的容量，以及 Fleet 容器的 CPU、内存占用和配额。主机数值覆盖整台 VPS，包括系统服务。文件系统数值表示容量占用，不是磁盘速度，也不是 Fleet 文件夹的大小。

把网关想成转交请求的路口，这些数值帮助判断路口是否拥挤。持续的 CPU 满载、可用内存很少、I/O 等待或 CPU 被宿主机占用，都可能帮助解释变慢；你的网络、选中的槽位和 Anthropic 也会耗时。单次空闲或繁忙的采样不能证明瓶颈在哪里。

可选的只读采样器每十五秒读取固定的 Linux proc 与容器自身 cgroup v2 数值计数器。页面只读取缓存，不调用模型。CPU 百分比需要两次观测；缺失或不支持的指标表示未知，超过一分钟的旧值不再显示。容器内存包含缓存与内核计入的占用；CPU 配额是使用上限，不是独占预留的核心。基础设施指标与用户流量分开，不需要转发尝试或计时样本。
