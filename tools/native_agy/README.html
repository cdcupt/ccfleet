CCFleet native agy verification

This macOS prototype runs two original Google CLI processes. The interactive client reviews four operations in a disposable Git repository. The headless slot calls their MCP equivalents and receives the client results. Both model endpoints use deterministic fixtures. This command verifies the integration and does not provide general-purpose Gemini chat.

Run on one Mac

python3 ccfleet_agent/gemini_native_check.py loopback .

Install Google’s agy on the Mac before starting. Complete the CLI’s first-run screens and trust the disposable folder. Allow the proof-file read if prompted, accept the edit to approved.txt, allow git rev-parse, and reject the edit to denied.txt. A passing run prints PASS after the backend receives the denial in the same conversation. Each run gets isolated profiles and a new repository.

Run through the private slot

The slot must have the matching opt-in handler installed and the client must have a Gemini workspace pairing. The client launcher uses the existing pinned SSH transport through ccfleet.io. Run the following command from the unpacked prototype, providing the directory in which to create the disposable repository.

./laptop/ccfleet gemini --native-check --project /path/to/project

Normal CCFleet pairing uses ./laptop/ccfleet pair gemini. An ordinary slot-device grant cannot run the check. A timeout or ambiguous operation ends the session. Restarting creates a fresh fixture. The denial observer uses the transcript layout verified in agy 1.5.14. No service tokens, personal OAuth profile, or Google model calls are needed for the fixture.

The included patch targets CCFleet source revision 1258d3f. It adds the slot handler, opt-in launcher, installer support, and focused tests. Applying source changes and activating a private-slot installation are separate actions. Google’s Antigravity FAQ excludes third-party headless wrappers from consumer-plan support.
