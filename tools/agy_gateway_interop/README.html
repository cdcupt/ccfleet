Native Antigravity file-tool interoperability

This opt-in macOS test checks whether the official Antigravity CLI can read and edit a local file through the OpenAI-compatible HTTP handler in agy-gateway. The gateway and CLI run on one Mac in separate sandboxes. The gateway has permission to learn the file contents only from the client’s tool response. The upstream ACP agent is scripted.

Reproduce the check

On a Mac with Python 3.9+, Git, Go 1.27.3+, and the official agy 1.5.14 CLI, run the following from the CCFleet checkout. Use --go and --agy to specify executable paths when needed.

python3 tools/agy_gateway_interop/check.py

Setup fetches the pinned public gateway source and its Go dependencies. The build then runs offline. During the test both processes use temporary homes, a fixture credential, and loopback networking. The test does not open a CCFleet production connection or submit a Google model request.

What passed

With default gateway settings, the native client received HTTP 400 because it sends max_completion_tokens. With the gateway’s documented compatibility setting, three consecutive runs returned the file’s random marker, performed a local edit, and delivered the final response. The gateway ignores the unsupported output-token limit in this mode. Recorded results.

This establishes client-tool compatibility. Consumer-subscription model serving through CCFleet remains unavailable. Google’s guidance on ACP usage.
