CCFleet Workspace for Mac

Open CCFleet Workspace in Finder on the Mac that holds your project. Choose a folder, then Antigravity and any test recipe you want to allow. During the first session, open Workspace app or older CLI in your slot’s Gemini settings, create a one-time code and paste it at the Ghostty prompt. Later sessions reuse that computer’s workspace pairing. Open subscription setup.

The official Google CLI runs in the slot owner’s macOS login session. Its built-in file and shell tools act on the slot. Ask it to use ccfleet-local-project for the selected project. The workspace tools send requested file contents and test output through the encrypted session to the agent. You approve saves, new folders and each test run on your computer. Test programs run with a temporary home, project-local write access and networking disabled. Project tools support UTF-8 files up to 192 KiB and skip sensitive or generated paths such as .git, .env and node_modules. To revoke access, remove that computer in Gemini settings.

Use T3 Code or the terminal

For T3 Code on your project Mac, run ccfleet update and ccfleet pair gemini. At the prompt, paste the reusable setup code from Gemini settings. Select Local ACP command in T3 and enter ccfleet with separate gemini and --acp arguments. Full T3 Code setup.

Run ccfleet gemini from the project directory for a terminal chat using the same pairing. Both clients use the Google sign-in on your private slot. The optional ccfleet gemini --preview runs a synthetic local file-edit check.

Enable another private Mac slot

The slot must be enrolled to its current administrator. Install Google's official CLI under ~/.local/bin/agy, complete Google's own sign-in on the slot, and deploy the workspace-capable CCFleet controller and Mac owner agent. From the matching source checkout, run the following in the slot owner's macOS login session.

/usr/bin/python3 tools/install_workspace_slot.py

The installer verifies the Google binary and starts a user LaunchAgent. The controller offers pairing after the next successful owner heartbeat. Existing device pairings retain their existing access. Each new subscription pairing has its own restricted device key. The private slot handles one interactive workspace session at a time.
