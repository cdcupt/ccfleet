CCFleet Workspace for Mac

Open CCFleet Workspace in Finder on the Mac that holds your project. Choose a folder, then Antigravity and any test recipe you want to allow. During the first session, copy the single-use code from your private slot’s subscription panel and paste it at the Ghostty prompt. Later sessions reuse that computer’s workspace pairing. Open subscription setup.

The official Google CLI runs in the slot owner’s macOS login session. Its built-in file and shell tools act on the slot. Ask it to use ccfleet-local-project for the selected project. The workspace tools send requested file contents and test output through the encrypted session to the agent. You approve saves, new folders and each test run on your computer. Test programs run with a temporary home, project-local write access and networking disabled. Project tools support UTF-8 files up to 192 KiB and skip sensitive or generated paths such as .git, .env and node_modules. Remove the workspace device under the slot's connected computers to revoke access.

Use the local command line

Run ccfleet claude in your project for Claude Code. The native ccfleet gemini --preview command starts Antigravity on the client Mac and sends model requests through the encrypted Fleet transport to its assigned slot. The slot uses a deterministic test response until a supported subscription endpoint is available. The preview exercises a disposable file in the selected project's directory without consuming model quota. The Finder launcher's interactive Antigravity mode runs on the private slot. Each native CLI launch checks its vendor release.

Enable another private Mac slot

The slot must be enrolled to its current administrator. Install Google's official CLI under ~/.local/bin/agy, complete Google's own sign-in on the slot, and deploy the workspace-capable CCFleet controller and Mac owner agent. From the matching source checkout, run the following in the slot owner's macOS login session.

/usr/bin/python3 tools/install_workspace_slot.py

The installer verifies the Google binary and starts a user LaunchAgent. The controller offers pairing after the next successful owner heartbeat. Existing device pairings retain their existing access. Each new subscription pairing has its own restricted device key. The private slot handles one interactive workspace session at a time.
